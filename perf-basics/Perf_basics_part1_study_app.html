1. What performance testing is (and isn't)

🚩 Why it matters: green functional tests ≠ capacity under traffic.

Perf checks speed and capacity goals under load. It does not replace unit/API/E2E correctness tests.

QuestionTool family
Does the journey work?Playwright / E2E
Is the contract right?API tests
Stay under X ms at N users?k6 / load tools
🧪 Self-test
Can Playwright alone guarantee p95 < 300 ms at 200 RPS?

No.

One question perf answers that unit tests don't?

Latency/error behavior under concurrent load.

4. k6 hello-world

🚩 Why it matters: run one script; read the table.

Lab file: labs/hello.js · Command: k6 run labs/hello.js · Install: k6 docs

import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 1,
  duration: '10s',
  thresholds: {
    http_req_failed: ['rate<0.01'],
    http_req_duration: ['p(95)<500'],
  },
};

export default function () {
  const res = http.get('https://test.k6.io');
  check(res, { 'status is 200': (r) => r.status === 200 });
  sleep(1);
}

⚠️ Never point early scripts at production.

What does vus: 1 mean?

One virtual user.

p95 800 ms vs threshold p(95)<500?

Threshold fails the run.

5. Interpreting p95

🚩 Why it matters: averages hide abandoners.

p95 = 95% of requests were faster than this number.

🧪 Live mock — percentile interpreter

Paste sample times and compute.
Mean fine, p95 terrible — meaning?

Tail latency: a small % of requests are very slow.

Prefer mean or p95 for user-facing SLO?

Prefer percentile (p95/p99).

8. Common pitfalls

🚩 Why it matters: bad tests create outages or false greens.
  1. Load-testing prod by accident
  2. Tiny samples labeled “p95”
  3. Mean-only reports
  4. E2E browsers as load generators
  5. No SLO before scripting
  6. High RPS with high errors
  7. Warm-cache only without saying so
🐞 Spot-the-Bug
“Perf OK — avg 120 ms” (15 samples, no p95/errors)

Too few samples; mean-only; missing errors/SLO.

500 Playwright workers in CI “for load”

Wrong tool; use k6 on APIs/non-prod.

11. Answer key

Practice answers
  1. SLI = login duration; SLO = e.g. p95 < 300 ms / week.
  2. Throughput · latency · load.
  3. { vus:5, duration:'30s', thresholds:{ http_req_duration:['p(95)<400'] } }
  4. E2E ≠ capacity under load.
  5. 900.
Challenge answers

C1. Tail risk at p99 — dig into outliers if that cohort matters.

C2. e.g. 99.9% of GET /home < 400 ms over 30 days.

C3. Keep E2E for journeys; add k6 + thresholds; report p95/errors.
