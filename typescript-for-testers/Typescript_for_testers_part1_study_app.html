1. Why TypeScript in automation

🚩 Why it matters: wrong helper args fail in the IDE, not after a long CI run.

TS adds static types on JS. Testers win on shared helpers, fixtures, and POM — safer refactors, earlier feedback.

Without TSWith TS
Wrong arg shape → CI fail laterRed squiggle at edit time
Rename field, miss call sitesEvery miss highlighted
🧪 Self-test
Do green E2E tests prove helper types are correct?

No.

One automation win from types?

Safer refactors of helpers/POM; fail fast in the IDE.

2. Primitive types & annotations

🚩 Why it matters: annotate helper params/returns first.
function isOk(status: number): boolean {
  return status >= 200 && status < 300;
}

Use unknown (then narrow) instead of any for unparsed JSON.

Annotate add(a,b) for numbers?

(a: number, b: number): number

any vs unknown for JSON?

Prefer unknown.

3. Interfaces

🚩 Why it matters: name fixture/API shapes once.
interface UserFixture {
  email: string;
  password: string;
  role: string;
}

Interface your objects — don't re-type the whole DOM (Playwright already typed Page/Locator).

🧪 Live mock — shape checker

Enter fields and click Build.
Re-type every DOM node?

No.

4. Unions

🚩 Why it matters: lock small sets of allowed values.
type TestResult = 'pass' | 'fail' | 'skip';
Better for env: string or 'dev'|'stage'|'prod'?

The union.

badge('passed') with TestResult?

Compile error — not in the union.

5. Optional properties

🚩 Why it matters: options objects are full of maybes.
interface ClickOptions {
  timeout?: number;
  force?: boolean;
}

opts?.timeout ?? 5000 — optional chaining + nullish coalescing.

Must email?: string be provided?

No — can omit.

?? vs || ?

?? only null/undefined; || also treats 0 and '' as missing.

7. Common pitfalls

🚩 Why it matters: any-spam deletes TS value.
  • any everywhere
  • Re-typing Playwright internals
  • @ts-ignore wallpaper
  • Over-modeling tiny fixtures
  • Thinking types replace behavior tests
Spot-the-Bug: setEnv(env: any) — fix?

env: 'dev' | 'stage' | 'prod'
