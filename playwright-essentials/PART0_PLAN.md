# PART0_PLAN — Testing Mindset (Strategy)

## Goal
Ship Part 0 of Playwright Essentials with three editions + labs alignment.

## Sections (11)
1. Why testing strategy exists — Strategy decides *what* to automate so you don't drown in brittle E2E.
2. The test pyramid — Many unit, fewer integration/API, fewest E2E — speed and signal.
3. Risk-based selection — Automate paths that hurt customers or revenue when broken.
4. When NOT to E2E — Pure logic, static pages, and anything already proven cheaper.
5. Flake vs product bug — Triage intermittent failures before rewriting product code.
6. Bug reports that help — Repro, expected vs actual, environment, artifacts.
7. Definition of done for tests — Deterministic, CI-green, readable failure messages.
8. Common strategy pitfalls — 100% E2E, testing implementation details, ignoring ROI.
9. Practice — Map one feature across pyramid layers.
10. Challenges — Classify scenarios into unit / api / e2e.
11. Answer key — Compare classifications.
