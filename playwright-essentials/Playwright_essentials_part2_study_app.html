1. Network Interception & Request Faking with page.route() ⏱ ~25 min

🚩 Why it matters: Testing against live third-party payment gateways or slow production APIs causes flaky, slow, and expensive test runs. Intercepting network requests lets you simulate 500 errors, slow 3G networks, and edge-case payloads instantly.

Playwright operates directly at the browser network protocol layer (CDP / Chromium DevTools Protocol). Using `page.route()`, Playwright can intercept outgoing HTTP requests made by your web application before they hit the real server, returning mock JSON responses, custom HTTP status codes (200, 401, 403, 500), or artificial network latency.

Complete Example
import { test, expect } from '@playwright/test';

test('Simulate 500 Internal Server Error from Payments API', async ({ page }) => {
  // Intercept any outgoing request matching the API route pattern
  await page.route('**/api/payments/checkout', async (route) => {
    // Fulfill the request with a mock HTTP 500 JSON response
    await route.fulfill({
      status: 500,
      contentType: 'application/json',
      body: JSON.stringify({
        error: 'InternalServerError',
        message: 'Payment gateway connection timed out.'
      })
    });
  });

  // Navigate to checkout UI and submit order
  await page.goto('/checkout');
  await page.getByRole('button', { name: 'Pay Now' }).click();

  // Verify UI correctly displays friendly error banner instead of crashing
  const errorAlert = page.getByRole('alert');
  await expect(errorAlert).toBeVisible();
  await expect(errorAlert).toContainText('Payment gateway connection timed out.');
});
page.route('**/api/payments/checkout', ...) — Glob pattern matching any network request sent to that endpoint.
route.fulfill({ status: 500, body: ... }) — Stops the request from reaching the real backend and returns mock HTTP 500 error.
page.getByRole("alert") — Validates that the web frontend handles backend failures gracefully.
🐞 Spot the Bug / Edge Case in this topic

Common Pitfall: Defining `page.route()` AFTER triggering the action (like clicking the Pay button).

Fix: Always register network route interceptors BEFORE triggering actions or navigating to the page.

🔮 Predict the Output / Behavior

Scenario: What happens if you call route.continue() inside page.route()?

Answer: Playwright allows the request to pass through to the actual live backend server normally.

🧪 Knowledge Check

Question: Why is mocking backend APIs with page.route() beneficial for frontend E2E testing?

✅ Answer: It isolates frontend UI testing, runs tests offline in milliseconds, and eliminates dependency on backend database state.

Rationale: Mocking ensures fast, deterministic, non-flaky test execution.

2. API Testing with request Context & Authentication Headers ⏱ ~25 min

🚩 Why it matters: Creating test data through the UI before every test takes 10x longer than creating data via direct REST API calls.

Playwright includes a built-in `request` context fixture that lets you issue HTTP GET, POST, PUT, DELETE requests directly to backend services without opening a browser window. This is ideal for fast API test automation and seeding test database state before UI tests run.

Complete Example
import { test, expect } from '@playwright/test';

test('Verify POST /api/users creates new user record', async ({ request }) => {
  // Issue direct REST API POST request
  const response = await request.post('http://localhost:3000/api/users', {
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer admin-secret-token-123'
    },
    data: {
      username: 'qa_automation_user',
      email: 'qa_test@example.com',
      role: 'tester'
    }
  });

  // Verify HTTP status code
  expect(response.status()).toBe(201);

  // Parse JSON response body
  const body = await response.json();
  expect(body).toHaveProperty('id');
  expect(body.username).toBe('qa_automation_user');
  expect(body.role).toBe('tester');
});
async ({ request }) => { ... } — Uses Playwright built-in APIRequestContext fixture for headless HTTP calls.
expect(response.status()).toBe(201) — Asserts HTTP 201 Created status code response.
await response.json() — Parses raw response buffer into a strongly-typed JavaScript object.
🐞 Spot the Bug / Edge Case in this topic

Common Pitfall: Forgetting `await` when calling `response.json()`, causing assertion against a pending Promise.

Fix: Always use `await response.json()` because JSON parsing is an asynchronous operation.

🔮 Predict the Output / Behavior

Scenario: What is returned by response.ok() if the API endpoint responds with HTTP 204 No Content?

Answer: It returns `true` because HTTP status codes 200–299 are considered OK by Playwright.

🧪 Knowledge Check

Question: How can you reuse authentication cookies/tokens across all Playwright tests in a suite?

✅ Answer: Use storageState in playwright.config.ts to save and load authenticated browser context state.

Rationale: `storageState` saves cookies and localStorage once, bypassing login steps for 100+ tests.
