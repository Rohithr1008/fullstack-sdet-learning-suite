1. Handling iFrames, Nested Frames & Dialog Modals ⏱ ~30 min

🚩 Why it matters: Third-party payment forms (Stripe, PayPal) and embedded editors live inside iFrames. Standard locators fail because iFrame elements belong to a separate nested DOM document.

💡 Explain Like I'm 5 (ELI5) / Beginner Analogy:

Think of an iFrame like a picture-in-picture TV window inside your living room TV screen:\n• Main Page = The outer living room TV screen.\n• iFrame = The small inner picture-in-picture window displaying a different TV channel.\n• `page.frameLocator()` = Pointing your remote control directly AT the small inner window so you can change its volume or channels without affecting the outer screen!

📖 Deep Conceptual Breakdown:

To interact with elements inside an iFrame, use `page.frameLocator(frameSelector)`. Playwright auto-waits for the frame to load and scopes locator searches strictly inside the inner frame document.\n\nHandling Native Browser Dialogs (Alert, Confirm, Prompt):\nBrowser dialogs block JavaScript execution. By default, Playwright automatically dismisses (cancels) all dialogs so tests do not hang. To accept a dialog or enter text into a prompt, register an event handler: `page.on("dialog", dialog => dialog.accept("My Input"))`.

Complete Example
import { test, expect } from '@playwright/test';

test('Interacting with Stripe Credit Card iFrame', async ({ page }) => {
  await page.goto('/checkout');

  // Scope locator inside nested payment iFrame
  const cardFrame = page.frameLocator('iframe[name="stripe-card-element"]');
  
  // Fill input fields inside iFrame
  await cardFrame.getByPlaceholder('Card number').fill('4242424242424242');
  await cardFrame.getByPlaceholder('MM / YY').fill('12/28');
  await cardFrame.getByPlaceholder('CVC').fill('123');

  // Submit outer page form
  await page.getByRole('button', { name: 'Complete Purchase' }).click();
});

test('Handling Native JS Alert & Prompt Dialogs', async ({ page }) => {
  // Register dialog listener BEFORE triggering dialog action
  page.on('dialog', async (dialog) => {
    console.log('Dialog Message:', dialog.message());
    console.log('Dialog Type:', dialog.type()); // 'alert' | 'confirm' | 'prompt'
    await dialog.accept('User Confirmation Input'); // Clicks OK / submits prompt text
  });

  await page.goto('/settings');
  await page.getByRole('button', { name: 'Delete Account' }).click();
});
page.frameLocator('iframe[name="..."]') — Scopes locator search inside nested iFrame DOM document.
page.on('dialog', async (dialog) => { ... }) — Registers event listener to intercept and accept browser alert/confirm/prompt modals.
await dialog.accept('...') — Sends OK response to browser dialog with optional input text.
🐞 Spot the Bug / Edge Case in this topic

Common Pitfall: Trying to use `page.locator()` directly on elements inside an iFrame without `frameLocator()`.

Fix: Always chain `page.frameLocator("iframe").getByRole(...)` to target elements inside frames.

🔮 Predict the Output / Behavior

Scenario: What is Playwright default behavior if a native browser alert dialog appears during a test?

Answer: Playwright automatically dismisses (cancels) all dialogs so the test does not hang.

🧪 Knowledge Check

Question: How do you target an input element nested inside an iFrame with Playwright?

✅ Answer: page.frameLocator("iframe#checkout").getByLabel("Card Number")

Rationale: frameLocator enters the frame context before finding the element.

2. Visual Regression Testing & Post-Mortem Debugging with Trace Viewer ⏱ ~35 min

🚩 Why it matters: Functional tests check if text exists, but miss broken CSS layout bugs (e.g. text overlapping buttons). Visual Regression testing compares page pixel snapshots automatically.

💡 Explain Like I'm 5 (ELI5) / Beginner Analogy:

Think of Visual Regression Testing like a spot-the-difference puzzle in a newspaper:\n• Baseline Snapshot = The master golden photo taken on Day 1.\n• New Test Snapshot = The photo taken today during the automated test build.\n• `expect(page).toHaveScreenshot()` = An automated scanner that overlays both photos and highlights any shifted pixels or color changes in bright magenta color!

📖 Deep Conceptual Breakdown:

Playwright built-in Visual Comparisons render page or element screenshots and compare them against golden baseline PNG files stored in your repository. If pixel differences exceed `maxDiffPixelRatio`, the test fails and generates a side-by-side visual diff report.\n\nPost-Mortem Debugging with Trace Viewer (`npx playwright show-trace`):\nWhen a test fails in CI, Playwright generates a `.zip` trace file containing full DOM snapshots before/after every action, network request/response headers, console logs, and action timelines. Opening the trace viewer lets you step backward and forward in time to inspect the exact failure moment!

Complete Example
import { test, expect } from '@playwright/test';

test('Visual Regression Snapshot Testing', async ({ page }) => {
  await page.goto('/');

  // Compare entire page pixel snapshot against baseline reference image
  await expect(page).toHaveScreenshot('landing-page.png', {
    maxDiffPixelRatio: 0.02, // Allow up to 2% pixel tolerance for font rendering differences
    mask: [page.getByTestId('dynamic-timestamp')] // Mask dynamic elements like clock/dates
  });
});
await expect(page).toHaveScreenshot(...) — Performs pixel-by-pixel visual comparison against baseline snapshot file.
maxDiffPixelRatio: 0.02 — Sets 2% tolerance threshold for minor sub-pixel rendering variations across OS runners.
mask: [page.getByTestId(...)] — Covers dynamic changing content (timestamps, ads) with solid pink box to prevent false failures.
🐞 Spot the Bug / Edge Case in this topic

Common Pitfall: Running visual tests on macOS locally and failing on Ubuntu CI due to font rendering differences.

Fix: Use Docker containers or `maxDiffPixelRatio` tolerance to ensure consistent cross-platform visual comparisons.

🔮 Predict the Output / Behavior

Scenario: How do you update golden baseline screenshots when UI design changes intentionally?

Answer: Run `npx playwright test --update-snapshots` (or `-u`).

🧪 Knowledge Check

Question: What command launches the interactive Playwright Trace Viewer GUI to inspect a failed test trace?

✅ Answer: npx playwright show-trace trace.zip

Rationale: Trace Viewer displays interactive DOM snapshots, network waterfalls, and action logs.
