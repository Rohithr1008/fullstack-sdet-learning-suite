Node & Express Essentials — Part 1: Event Loop & REST Routing

1. How Node.js Handles 10,000 Requests Simultaneously ⏱ ~15 min

💡 Beginner Metaphor: Imagine a restaurant with 1 Waiter (Node's Single Thread) and 5 Chefs in the Kitchen (C++ Worker Threads in libuv). The waiter takes an order, hands it to the kitchen, and immediately takes the next customer's order without standing around waiting for the steak to cook!

Traditional servers (like Java Tomcat or PHP Apache) create a new heavy OS thread for every single HTTP user. If 1,000 users connect, memory fills up and the server crashes. Node.js uses Non-Blocking I/O so a single thread can serve thousands of concurrent connections!

const fs = require('fs'); console.log('1. Customer places order (Start)'); // Non-blocking asynchronous file read fs.readFile('menu.json', 'utf8', (err, data) => { if (err) throw err; console.log('3. Kitchen finished cooking (File loaded callback)!'); }); console.log('2. Waiter takes next customer order (End of main thread loop)');

Line-by-Line Breakdown:

console.log('1...'): Main JavaScript thread executes synchronously. Output: 1. Customer places order.
fs.readFile(...): Node delegates hard disk I/O to libuv background thread. The main thread DOES NOT WAIT and keeps moving!
console.log('2...'): Main thread finishes synchronously. Output: 2. Waiter takes next customer order.
(err, data) => { ... }: When disk reading finishes, libuv places callback into the Event Queue. Main thread executes it. Output: 3. Kitchen finished...
