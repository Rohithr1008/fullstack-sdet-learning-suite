1. Password Hashing with bcrypt & JWT Token Security ⏱ ~35 min

🚩 Why it matters: Storing plain-text passwords in a database is a severe security violation. Using JWT (JSON Web Tokens) provides stateless, secure authentication across microservices.

💡 Explain Like I'm 5 (ELI5) / Beginner Analogy:

Think of JWT Authentication like a Wristband at a Music Festival:\n1. Login = You show your ID card at the entrance (Username/Password). The gatekeeper verifies it and seals a tamper-proof VIP Wristband around your wrist (JWT Token).\n2. Subsequent Requests = You don't show your ID card again! You just show your VIP Wristband (Authorization: Bearer Token) to enter any stage or buy drinks!

📖 Deep Conceptual Breakdown:

Passswords MUST be hashed using adaptive cryptographic functions like `bcrypt` with a salt cost factor (e.g. 10 or 12 rounds) before saving to PostgreSQL or MongoDB.\n\nJSON Web Tokens (JWT) consist of 3 Base64URL-encoded parts separated by dots (`Header.Payload.Signature`). The signature is cryptographically signed using a secret key on the server, guaranteeing that clients cannot tamper with their user role or user ID inside the token.

Complete Example
const bcrypt = require('bcrypt');
const jwt = require('jsonwebtoken');

// 1. Password Hashing on Registration
async function hashPassword(plainPassword) {
  const saltRounds = 10;
  return await bcrypt.hash(plainPassword, saltRounds);
}

// 2. Token Generation on Login
function generateAccessToken(user) {
  return jwt.sign(
    { userId: user.id, role: user.role },
    process.env.JWT_SECRET,
    { expiresIn: '1h' }
  );
}

// 3. Express JWT Verification Middleware
function authenticateToken(req, res, next) {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1]; // Extract Bearer token

  if (!token) return res.status(401).json({ error: 'Access token required' });

  jwt.verify(token, process.env.JWT_SECRET, (err, decodedUser) => {
    if (err) return res.status(403).json({ error: 'Invalid or expired token' });
    req.user = decodedUser;
    next();
  });
}
await bcrypt.hash(plainPassword, 10) — Cryptographically hashes password with 10 salt rounds.
jwt.sign({ userId, role }, SECRET, { expiresIn: "1h" }) — Signs payload into a JWT token valid for 1 hour.
authHeader.split(' ')[1] — Extracts token string from `Authorization: Bearer ` header.
🐞 Spot the Bug / Edge Case in this topic

Common Pitfall: Storing JWT secret keys hardcoded in Git source code repository instead of environment variables (`.env`).

Fix: Always store JWT secrets in `.env` environment variables and include `.env` in `.gitignore`.

🔮 Predict the Output / Behavior

Scenario: What HTTP status code should Express return if a client sends an expired JWT token?

Answer: HTTP 403 Forbidden (or 401 Unauthorized).

🧪 Knowledge Check

Question: Why is bcrypt preferred over MD5 or SHA256 for password storage?

✅ Answer: bcrypt includes salt and is intentionally slow (key stretching), making brute-force rainbow table attacks infeasible.

Rationale: SHA256 is too fast, allowing GPUs to test millions of passwords per second.
