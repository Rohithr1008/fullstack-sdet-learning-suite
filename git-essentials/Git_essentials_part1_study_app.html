Git Essentials — Part 1: Foundations & Core Commands

Master version control from absolute zero. Learn how Git tracks changes, stages files, and maintains revision history.

1. What is Version Control & Why Git? ⏱ ~8 min

Git is a distributed version control system (DVCS). Unlike central backups, every developer's machine holds a complete copy of the repository history.

  • Track History: Know exactly who changed what line, when, and why.
  • Time Travel: Revert code back to any state in history if bugs are introduced.
  • Collaboration: Merge changes from multiple developers safely.
💡 Quiz: What makes Git "distributed"?

Every developer has a full copy of the entire repository and its history locally, allowing full offline commits and history inspection.

2. Initializing & Staging Files ⏱ ~10 min

Git has 3 main states: Working Directory, Staging Area (Index), and Repository (.git).

# Initialize a new Git repository
git init

# Check repository status
git status

# Add files to the staging area
git add index.html
git add .  # Stages all files

3. Committing & History Log ⏱ ~12 min

Commits create snapshot checkpoints in your history. Always write meaningful commit messages.

# Commit staged changes
git commit -m "feat: add user authentication form"

# View commit history
git log --oneline --graph
