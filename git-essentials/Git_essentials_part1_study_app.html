1. Understanding Git: The Three Trees (Working Directory, Staging Area, Commit History) ⏱ ~30 min

🚩 Why it matters: Git is the universal standard for source code version control. Without Git, team members overwrite each other code, and there is no way to revert broken production bugs.

💡 Explain Like I'm 5 (ELI5) / Beginner Analogy:

Think of Git like taking photos for a photo album:\n1. Working Directory = Your living room where you get people dressed up and arranged (editing files on your computer).\n2. Staging Area (Index) = Posing everyone in front of the camera lens and checking the frame (running `git add` to review what changes are about to be saved).\n3. Commit History (Repository) = Pressing the camera shutter button to take a permanent snapshot and gluing the photo into your permanent photo album (running `git commit`). You can flip back to any photo snapshot taken in the past whenever you want!

📖 Deep Conceptual Breakdown:

Git manages your project files across 3 distinct zones:\n\n• Working Directory: The actual physical files on your hard drive that you edit in VS Code. Files here can be Untracked (new) or Modified.\n• Staging Area (Index): A temporary prep area holding snapshots of changes you explicitly want to include in the next commit. `git add filename` moves files into Staging.\n• Local Repository (.git folder): A permanent cryptographic database holding all historical commits. `git commit -m "msg"` records the staged snapshot with a unique SHA-1 hash key (e.g. `4c179ec`), author timestamp, and commit message.

Complete Example
# 1. Initialize a new Git repository in current folder
git init

# 2. Check current status of Working Directory and Staging Area
git status

# 3. Stage specific modified file (move to Staging Area)
git add src/app.js

# 4. Or stage all modified & new files in current folder
git add .

# 5. Create a permanent historical snapshot with descriptive commit message
git commit -m "feat: add user login form validation logic"

# 6. View commit log history timeline
git log --oneline
git init — Creates hidden .git directory inside folder, turning it into a Git repository.
git status — Displays which files are modified, staged for commit, or untracked.
git add . — Stages all changed files in current directory into the Staging Index.
git commit -m "..." — Takes snapshot of staged files and saves it permanently to local Git repository.
🐞 Spot the Bug / Edge Case in this topic

Common Pitfall: Running `git commit` without running `git add` first, resulting in "nothing to commit, working tree clean".

Fix: Always stage files with `git add` before running `git commit`.

🔮 Predict the Output / Behavior

Scenario: What happens if you edit app.js after running `git add app.js` but BEFORE running `git commit`?

Answer: The commit will only save the version of app.js at the moment `git add` was executed. The new edits remain unstaged in Working Directory.

🧪 Knowledge Check

Question: Which Git command moves changed files from the Working Directory into the Staging Area?

✅ Answer: git add

Rationale: git add prepares and stages files for the upcoming commit snapshot.
