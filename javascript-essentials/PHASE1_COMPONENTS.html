🧪 Enhanced Quiz Example — Variables

Q1. What does const actually prevent?
✅ Reassigning the variable to a new value

Why: `const` locks the binding (variable reference), not the contents. You can't do `person = {}`, but you CAN do `person.name = "new"` because you're modifying the object's contents, not reassigning the variable.

❌ Changing an object's contents

Why this is wrong: This is actually allowed! `const` only locks the binding, not the object's properties. Objects and arrays are mutable, and `const` doesn't change that.

Q2. What happens if you forget break in a switch case?
✅ Execution "falls through" into the next case

Why: Without `break`, JavaScript doesn't stop after a matching case—it continues executing code in subsequent cases. This is often a bug. Example:

switch(2) {
  case 1: console.log("A");
  case 2: console.log("B");  // matches
  case 3: console.log("C");  // still runs!
}
// Output: B, C (not what we wanted)
❌ JavaScript throws an error

Why this is wrong: No error is thrown. The fall-through happens silently, which is what makes this so dangerous.

🐞 Spot the Bug! (Expanded Version)

Find the mistake in each code snippet:

🟢 Bug #1 (Easy): Variables — `const` and reassignment 
const name = "Rohit";
name = "Amit";  // ❌ BUG HERE
console.log(name);
✅ The bug: Can't reassign a `const` variable. Error: `TypeError: Assignment to constant variable`
🟢 Bug #2 (Easy): Conditions — missing `break` in switch 
const day = "Monday";
switch(day) {
  case "Monday":
    console.log("Start of week");
    // ❌ Missing break here
  case "Friday":
    console.log("Almost weekend");
    break;
}
// Output: "Start of week" AND "Almost weekend"
✅ The bug: Missing `break` causes fall-through to the next case.
🟡 Bug #3 (Medium): Loops — infinite loop 
let i = 0;
while (i < 10) {
  console.log(i);
  // ❌ i never increments!
}
// Output: 0 0 0 0 0 ... (infinite)
✅ The bug: Missing `i++` creates an infinite loop. Browser will hang.
🟡 Bug #4 (Medium): Arrays — `map` without return 
const nums = [1, 2, 3];
const doubled = nums.map(x => { x * 2 }); // ❌ No return!
console.log(doubled);
// Output: [undefined, undefined, undefined]
✅ The bug: Braces `{}` without `return` keyword = no value returned. Fix: Either remove braces (`x => x * 2`) or add `return` (`=> { return x * 2; }`).
🟡 Bug #5 (Medium): Arrays — Mutating during iteration 
const arr = [1, 2, 3, 4, 5];
arr.forEach(x => {
  if (x % 2 === 0) {
    arr.splice(arr.indexOf(x), 1);  // ❌ Don't mutate during loop!
  }
});
// Output: [1, 3, 5] — but unreliable!
✅ The bug: Modifying an array while looping over it causes items to be skipped. Use `filter()` instead.
🔴 Bug #6 (Hard): Objects — Mutation via reference 
const original = { name: "Rohit", tags: ["JS"] };
const copy = { ...original };
copy.tags.push("Python");  // ❌ BUG: Affects original!
console.log(original.tags);
// Output: ["JS", "Python"] — original changed!
✅ The bug: Spread `{...}` is a shallow copy. Nested objects/arrays are still shared. Use `structuredClone()` for deep copy.
🔴 Bug #7 (Hard): Strings — Immutability trap 
let str = "hello";
str[0] = "H";  // ❌ Strings are immutable
console.log(str);
// Output: "hello" (unchanged)
✅ The bug: Strings can't be changed via index assignment. Build a new string: `str = "H" + str.slice(1)`.
🔴 Bug #8 (Hard): Operators — Type coercion surprise 
const result = "5" + 3 - 2;  // ❌ What's the result?
console.log(result);
// Output: 50 (not 6!)
✅ The bug: `"5" + 3` = `"53"` (string concat). Then `"53" - 2` = `51` (coerced to number, then subtracted). Always use `===` and be aware of type coercion with `+`.
