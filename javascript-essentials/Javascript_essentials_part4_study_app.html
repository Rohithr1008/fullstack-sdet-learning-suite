1. Hello MERN — the 3-layer sandwich

🚩 Why it matters: one picture in your head — three layers talking to each other.
┌───────────────────────────────┐
│ 🟣 React  "the screen"          │  what the user sees
│      │  fetch("/api/notes")     │  JS run in the browser
│      ▼                          │
│ 🟢 Express "the receptionist"   │  decides the route + rule
│      │ "give me all notes"      │  JS run on the server
│      ▼                          │
│ 🟡 MongoDB "the filing cabinet" │  stores documents
└───────────────────────────────┘

The one sentence: the screen (React) phones the server (Express); the server saves/finds it in MongoDB, sends the answer back, and React redraws the screen.

5. REST API design

7. Project A — Notes backend

app.use(cors());             // let the React frontend call us

  res.json(await Note.find().sort({ createdAt: -1 }));

  res.status(201).json(await Note.create(req.body));
});
app.get("/api/notes/:id", async (req,res) => {
  const n = await Note.findById(req.params.id);
  if (!n) return res.status(404).json({ error: "Not found" });
  res.json(n);
});
app.put("/api/notes/:id", async (req,res) =>
  res.json(await Note.findByIdAndUpdate(req.params.id, req.body, { new: true })));
app.delete("/api/notes/:id", async (req,res) => {
  await Note.findByIdAndDelete(req.params.id); res.status(204).end();
});
app.listen(3000, () => console.log("Notes API on :3000"));

9. Client → server — fetch in React

🚩 Why it matters: the moment the 🟣 screen talks to the 🟢 server — it's the fetch from Part 3, wired into state.
async function loadNotes() {
  const res  = await fetch("http://localhost:3000/api/notes");
  if (!res.ok) throw new Error("HTTP " + res.status);
  setNotes(await res.json());
}
async function addNote(text) {
  const res = await fetch(".../api/notes", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ text }),
  });
  setNotes((prev) => [await res.json(), ...prev]);
}

The 4-step pattern: fetch → check res.ok → .json() → setState (re-render).

15. Common pitfalls in MERN

🚩 Why it matters: the exact bugs that waste beginners' hours — recognize once, skip the pain.
// 1. Forgot await on Mongoose
const notes = Note.find();          // ❌ promise, not data
const notes = await Note.find();    // ✅

// 2. Forgot res.ok check
const d = await res.json();         // ❌ confusing on 404/500
if (!res.ok) throw new Error(...);  // ✅ check first

// 3. Mutating state
notes.push(x); setNotes(notes);     // ❌ no re-render
setNotes((prev) => [...prev, x]);            // ✅ new array via functional updater

// 4. findByIdAndUpdate returns OLD doc without { new: true }
Note.findByIdAndUpdate(id, upd);                   // ❌ old
Note.findByIdAndUpdate(id, upd, { new: true });    // ✅ new

// 5. CORS: add app.use(cors()) on the SERVER
// 6. Empty req.body: add app.use(express.json())

17. Answer key

🚩 Why it matters: compare your work — noticing differences is where learning happens.

🔑 Challenge solutions

C1 — makeProduct

❌ Returning a string — you need a product object shape

✅ Canonical solution — return { name, price, reviews: [] }

function makeProduct(name, price) {
  return { name, price, reviews: [] };
}
C2 — addReview

❌ Mutating product.reviews.push — immutability keeps React happy

✅ Canonical solution — return a new object with spread reviews

function addReview(product, review) {
  return { ...product, reviews: [...product.reviews, review] };
}
C3 — routePath

❌ Concatenating blindly — replace the :id token

✅ Canonical solution — template.replace(":id", id)

function routePath(template, id) {
  return template.replace(":id", id);
}
C4 — pickStatus

❌ Always returning 200 — verbs map to different statuses

✅ Canonical solution — POST→201, GET→200, DELETE→204

function pickStatus(verb) {
  if (verb === "POST") return 201;
  if (verb === "GET") return 200;
  if (verb === "DELETE") return 204;
  return 500;
}
C5 — avgRating

❌ Dividing by zero blindly — empty list should return 0

✅ Canonical solution — guard empty, then reduce/length

function avgRating(items) {
  if (!items || items.length === 0) return 0;
  return items.reduce((s, r) => s + r, 0) / items.length;
}
C6 — validateNote

❌ Always returning valid:true — empty text must fail

✅ Canonical solution — reject empty/whitespace text

function validateNote(note) {
  if (!note.text || note.text.trim() === "") return { valid:false, error:"text is required" };
  return { valid:true };
}
