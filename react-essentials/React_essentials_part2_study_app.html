1. Managing Side Effects with useEffect & Dependency Arrays ⏱ ~30 min

🚩 Why it matters: Web applications must fetch data from backend REST APIs, set up WebSocket connections, and update browser page titles. Performing these actions directly inside a component body causes infinite render loops!

💡 Explain Like I'm 5 (ELI5) / Beginner Analogy:

Think of useEffect like an automatic robot assistant assigned to a room:\n• Component Render = Turning the light on in the room.\n• useEffect = The robot steps in ONLY when specific items change (e.g. "When a new user ID arrives, go fetch their profile data from the server").\n• Dependency Array `[]` = The robot instruction manual telling it when to run:\n - Empty array `[]` = Run ONCE when the room is built (component mounts).\n - Array `[userId]` = Run whenever `userId` changes.\n - No array = Run EVERY single time the room light turns on (infinite loop risk!).

📖 Deep Conceptual Breakdown:

In React, rendering should be a pure function of props and state. Side effects (data fetching, DOM mutations, timers, subscriptions) must be isolated inside `useEffect()`.\n\nThe cleanup function returned by `useEffect` (e.g. `return () => clearInterval(timer)`) prevents memory leaks when components unmount or re-render.

Complete Example
import React, { useState, useEffect } from 'react';

export function UserProfileCard({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    let isMounted = true;
    setLoading(true);

    fetch(`/api/users/${userId}`)
      .then(res => res.json())
      .then(data => {
        if (isMounted) {
          setUser(data);
          setLoading(false);
        }
      });

    // Cleanup function: runs before component unmounts or userId changes
    return () => {
      isMounted = false;
    };
  }, [userId]); // Dependency Array: re-runs effect whenever userId changes

  if (loading) return 
Loading user profile...
;
  return 
{user.name}
{user.email}
;
}
useEffect(() => { ... }, [userId]) — Effect hook containing side effect logic, triggered when `userId` updates.
return () => { isMounted = false; } — Cleanup function preventing state updates on unmounted components (memory leak fix).
🐞 Spot the Bug / Edge Case in this topic

Common Pitfall: Forgetting the dependency array `[userId]`, causing `useEffect` to trigger infinite API fetch requests.

Fix: Always specify an explicit dependency array `[deps]` for every `useEffect` hook.

🔮 Predict the Output / Behavior

Scenario: When does a useEffect cleanup function execute?

Answer: Right before the component unmounts or before re-running the effect on dependency change.

🧪 Knowledge Check

Question: What happens if you pass an empty array `[]` as the second argument to `useEffect`?

✅ Answer: The effect runs only ONCE after the initial component mount.

Rationale: An empty dependency array indicates no state triggers re-running the effect.
